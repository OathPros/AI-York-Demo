# AI @ York demonstration site

This repository contains the first connected prototype from `AI-YORK-BUILD-PLAN.md`: a GitHub Pages React app and a Cloudflare Worker backed by local or remote D1.

## Local development

```powershell
npm install
npm run import:reference
npm run db:migrate
npm run db:seed
```

Run the API and web app in separate terminals:

```powershell
npm run dev:api
npm run dev:web
```

The local demo does not require a Cloudflare account. Use the role chooser to start a workspace, submit an event, switch to Studio, copy a visitor link, and publish the event. The visitor link can be opened in another browser and cannot elevate that browser into Studio.

## Deployment configuration

Set `database_id` in `apps/api/wrangler.toml` to the dedicated D1 database. Configure `ALLOWED_ORIGINS` for the Pages URL and local development. The Pages environment needs `VITE_API_BASE_URL`; the Worker workflow needs `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. Remote migrations are intentionally manual through the Worker workflow.

The GitHub Pages custom domain `https://lukegagliardi.com` is included in `ALLOWED_ORIGINS`. Changes to this setting require a Worker deployment via the manually triggered Deploy Worker workflow; a Pages deployment alone cannot update CORS.

The supplied homepage and Studio navigation references remain under `docs/references`. Imported demonstration data is generated by `npm run import:reference` into `apps/api/fixtures/reference-content.json` and `.sql`; the importer validates all 90 guidance cases, six tools and 11 sources without executing the reference scripts.

## Live demo and CMS

- Site: https://ai-york-demo.pages.dev  API: https://ai-york-demo-api.luke-gagliardi.workers.dev
- Studio (demo admin role) has a Content inventories tab to manage policy, interpretation, tool, event, community and training items.
- Shared base content (D1 `content_items`, workspace_id='base') is seeded by `npm run import:reference` + `db:seed`; workspace edits override base rows by id and never change shared content.
- Sessions use bearer tokens (sessionStorage).
- Studio's POLICY and Interpretations views embed the supplied Policy Studio proof of concept. The policy on the public governance page reflects those edits in the same browser, including across tabs. Its fictional roles, approvals, notifications and records are browser-local simulations: they are not shared with other users or published to the CMS. Use export and reset to manage the demo state.
- Guidance and training filters and program levels have shareable hash URLs; existing audience, learning, policy and community links remain available. Training records can specify activities and program level in Studio. Older records use their existing tags and a small set of explicit seed classifications until edited.
- Placeholders: news, governing bodies, Ask AI @ York chatbot; communities/events are empty until added.
